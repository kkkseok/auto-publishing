공식 기술 참고: [Meta Threads API collection](https://www.postman.com/meta/threads/documentation/dht3nzz/threads-api).
Meta 약관/개발자 정책 페이지 직접 조회는 접근 오류/HTTP 429로 실패했다. 이번 문서의 제한 조항 해석은 제공된 대시보드 문구 범위에 한정한다.

## Meta에 제출할 내용

`appeal_text_v3.txt`는 기존 설명의 부정확한 부분을 정정하고 구체적인 위반 행위와 남은 요건을 묻는 영어 초안이다. 제공된 화면의 두 질문은 다음처럼 사실에 맞게 구분해야 한다.

1. **어떻게 위반했는지 이해했나요?** 일반적인 7.e.i.2 안내만 받았다면 구체적 위반 행위는 아직 확인하지 못했다는 답변이 정확하다. 추정 원인을 Meta가 확인한 사실처럼 인정하지 않는다.
2. **필요한 변경을 완료했나요?** 자체 감사에서 확인한 변경은 완료했다. 다만 Meta가 요구하는 모든 조치가 끝났다는 확인은 없다. 추가 설명란에는 이 범위를 명시한다. 선택지만 있고 설명할 수 없다면 미확인 요건까지 완료했다고 주장하지 않는다.

첨부 권장: 이번 PDF, `local_audit.json`, 필요 시 이번 코드 diff 및 테스트 파일. 이전 8월/9월 증빙을 새 구현의 증거처럼 재사용하지 않는다. 전체 .env, 토큰, 앱 시크릿, 브라우저 쿠키는 첨부하지 않는다.

제출 전에 대시보드/지원함에서 확인해야 하는 미확인 항목:

- 두 거절 건의 실제 응답 문구, 사건번호와 날짜.
- 앱 제한 외 개발자 계정 또는 연결된 Threads/Instagram 계정의 제한 여부.
- 앱 설정에 요구되는 개인정보 처리방침/데이터 삭제 정보, 앱 연락처, 권한 상태의 누락 여부. 현재 접근하지 못했으므로 결함으로 단정하지 않는다.
- `THREADS_APP_ID`는 Threads 전용 앱 ID일 수 있으며 화면의 상위 Meta 앱 ID와 단순히 다르다는 이유로 잘못된 값으로 교체하지 않는다.

Meta 제출은 아직 하지 않았다. 제공된 도구에는 로그인된 Meta 대시보드를 직접 조작하는 연결이 없다.

## 복구 후 순서

1. Meta 대시보드의 제한 해제와 관련 통지/사건번호를 확인한다.
2. `python -m common.threads_access resume --reference <복구통지-사건번호>`로 운영자 확인을 기록한다. 이 명령 자체는 Meta 상태를 검증하지 않는다. API 오류로 프로세스 내부에도 중지 상태가 걸렸다면 해당 프로세스를 재시작한다.
3. 토큰 상태를 확인하고, 필요 시 변경된 최소 권한 OAuth를 실행한다. 이전에 부여된 권한은 별도 확인이 필요하다.
4. 기존 발행량 기록을 대조한 뒤 검수된 게시물 1건으로 재개한다. 예약은 자동으로 복원되지 않는다. 제휴 비율을 맞추려고 의미 없는 게시물을 추가하지 않는다.

Graphify 갱신은 현재 환경에 실행 파일/패키지가 없어 수행하지 못했다.
