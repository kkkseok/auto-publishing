# 문체·양식 가이드 v1.0 (블로그 A/B/C/D)

작성일 2026-10-15. 근거: `261015_상위블로그-양식분석-노트.md` (Naver 상위 30편 직접 측정 + Google 대체 표본 9편).
표기: [관찰] = 표본에서 확인된 사실, [추정] = 일반 SEO 원칙·판단(표본으로 검증 안 됨).
예시 문장은 모두 이 문서에서 새로 쓴 것이며 상위 글 문장이 아니다.

## 0. 공통 원칙 (4개 블로그 전부)

1. 정보는 "근거 + 기준일"이 한 쌍. 숫자 옆에 출처(기관명)와 확인일을 붙인다. [관찰] 상위 글 중 기준일을 적은 글은 소수라 차별점이 된다.
2. 결론은 위에. 첫 화면(스크롤 전)에 "한 줄 결론 또는 3줄 요약"이 있어야 한다. [관찰] 정책 글 상위 다수가 질문형/결론형 도입.
3. 소제목은 독자 질문 그대로(누가·언제·얼마·어떻게). 장식 소제목 지양.
4. 표는 "비교·수치·일정"에만 쓴다. 문단을 표로 바꾸지 않는다.
5. 불확실하면 단정하지 않고 "아직 발표 전" 처럼 상태를 적는다. [관찰] 이런 정직한 기준 표기가 연말정산 상위에 존재.
6. 제휴(쿠팡/알리) 문구는 `common/affiliate_notice.py`의 규칙만 사용: 본문 최상단, 시각 구분(굵은 빨강 박스), "제공받습니다" 단정형. 상위 글은 본문 내 고지가 거의 없었지만 우리는 따르지 않는다.
7. 최소 발행 게이트(MIN_POST_VISIBLE_CHARS)와 얇은 글 방지 규칙(애드센스 대응)을 우선한다. 아래 길이는 "본문 공백 제외" 기준 하한과 권장.
8. 개인 경험을 지어내지 않는다. "써봤다", "방문했다" 류 후기 문체는 사실이 있을 때만(우리 파이프라인은 대부분 데이터형이므로 사용 금지).

## 1. 블로그 A: Naver · 생활정보·정책

### 1.1 상위 글 패턴 요약 [관찰]
- 길이 평균 약 2,150자(범위 750~4,240), 이미지 평균 8장, 표 포함 9/15, 합니다체 약 85%, FAQ 4/15, 본문 내 공식 출처 4/15, 해시태그 약 60%.
- 제목은 키워드 앞배치(80%), 연도 표기, 괄호로 "대상·기간·신청방법" 범위 나열, 또는 질문형·따옴표 후킹.
- 소제목은 Naver 인용구 컴포넌트를 소제목처럼 사용(10~13개까지도). 질문형·번호형.
- 모바일 읽기: 한 문단 1~3문장, 줄바꿈 잦음.

### 1.2 제목 공식 (30~45자)
- 공식 1: `[연도] 키워드 + 괄호(대상·기간·방법)` 예: `2026 에너지바우처 신청, 대상·기간·사용법 한 번에 정리`
- 공식 2: `키워드 + 놓치기 쉬운 포인트(숫자)` 예: `근로장려금 신청 전 확인할 3가지, 기한후신청까지`
- 공식 3: `키워드 + 질문` 예: `연말정산 간소화 서비스, 올해는 언제 열릴까?`
- 규칙: 키워드는 앞 15자 안. 연도는 신청/귀속 연도를 명확히(귀속연도 혼동 주의). 따옴표 후킹은 사실 기반 숫자일 때만.

### 1.3 섹션 순서 템플릿
1. (최상단) 기준일 한 줄: `2026.10.15 기준 · 출처: 국세청, 복지로`
2. 도입 2~3문장: 상황 공감 -> 결론 한 줄
3. 3줄 요약 박스(대상/기간/방법 또는 금액)
4. 소제목 1: 누가 대상인가 (표: 구분 / 기준)
5. 소제목 2: 얼마를 받나/내나 (표: 가구유형 / 기준 / 금액)
6. 소제목 3: 언제까지, 어디서 (일정 표: 날짜 / 내용)
7. 소제목 4: 신청 방법 단계 (번호 목록 + 공식 화면 캡처 2~4장)
8. 소제목 5: 자주 놓치는 점·예외 (체크리스트)
9. FAQ 3~5문항 (Q/A 짧게)
10. 마무리 + 출처 목록 + 면책 한 줄 + 해시태그 5~8개

### 1.4 분량·표·이미지
- 본문 1,800~2,800자(공백 제외). 하한 1,500. 복잡 주제(연말정산)만 3,500까지.
- 표 2~3개: 대상 기준표, 금액표, 일정표 중 해당되는 것. 열 2~4개, 행 3~8개.
- 이미지 5~9장: 공식 사이트 화면 캡처(번호 단계마다), 금액 인포그래픽 1장. 장식 이미지 지양. [관찰] 이미지 위주의 짧은 글(750자)은 상위에서도 약했음.
- 강조: 굵은 글 + 필요 시 색(1~2색). 핵심 숫자만.

### 1.5 도입·마무리 템플릿 (신규 작성)
도입: `연말이 다가오면 올해 공제를 어디서부터 챙겨야 할지 막막해지죠. 결론부터 말하면, 가장 먼저 확인할 것은 [핵심 한 가지]입니다. 아래에서 대상과 일정, 신청 순서를 차례로 정리했어요.`
마무리: `정리하면 이번 신청의 핵심은 [기한]과 [대상 확인] 두 가지입니다. 기준이 바뀔 수 있으니 신청 전 [공식 사이트]에서 한 번 더 확인해 주세요. 도움이 되셨다면 이웃 추가로 일정 변경 소식을 받아 보세요.`

### 1.6 문체
- 기본 합니다체(신뢰) + 문장 끝 일부 해요체로 부드럽게 혼용 가능. 한 글 안에서 비율을 일정하게.
- 예시: `신청은 홈택스나 손택스에서 5분이면 끝납니다.` / `안내문이 없어도 대상일 수 있어요. 아래 기준부터 확인해 보세요.`
- 이모지: 소제목 앞 0~1개 허용, 본문 5개 이하. [관찰] 대량 이모지(25~33개)는 소수.

## 2. 블로그 B: Naver · 가격 데이터형 쇼핑

### 2.1 상위 글 패턴 요약 [관찰]
- 길이 평균 약 2,110자(범위 835~3,350), 이미지 평균 10장(후기형 18~29), 표 포함 3/15, 해요/합니다 혼재, 제휴는 쇼핑커넥트·브랜드커넥트 링크, 본문 내 고지 문구 거의 없음.
- 가격 추이·확인일을 적은 글은 30편 중 2편뿐. 대부분 "후기/스펙 소개". 비교표는 소수 -> **날짜가 박힌 가격표/추이**가 빈자리 [추정: 경쟁 약함].
- 로봇청소기 1위: "3줄 요약 -> 핵심 사양 한눈에 -> 제품별 -> FAQ -> 참고자료+확인일" 구조.

### 2.2 제목 공식 (30~45자)
- 공식 1: `제품명 가격 추이, 지금이 살 타이밍일까 (10월 기준)`
- 공식 2: `카테고리 추천 TOP N, 최근 최저가와 함께 비교`
- 공식 3: `제품 A vs 제품 B, 가격 차이와 선택 기준`
- 규칙: 제품/카테고리 키워드 앞배치, "최저가·가격 추이·타이밍" 중 1개, 기준 월을 괄호로. "역대 최저가"는 데이터로 확인된 경우에만.

### 2.3 섹션 순서 템플릿
1. (최상단) 제휴 고지 박스(affiliate_notice 규칙) + 가격 기준일 한 줄
2. 도입 2문장: 구매 고민 -> 이 글의 결론
3. 3줄 요약: 현재가 / 최근 N일 최저·평균 / 한 줄 판단
4. 가격 추이 소제목: 기간별 가격 표(날짜 / 최저가 / 평균 / 판매처) 또는 차트 이미지
5. 구매 타이밍 소제목: 할인 시즌·카드/쿠폰 조건 (근거 있는 것만)
6. 제품 비교 소제목: 스펙 비교표(제품 / 핵심 스펙 / 가격대 / 추천 대상)
7. 제품별 짧은 설명 (소제목은 `제품명 + 특징 한 구절`)
8. 선택 기준 체크리스트 (5~7개)
9. FAQ 3문항 (가격 알림, 정품 구분, 렌탈/할부 등)
10. 마무리 + 데이터 출처·확인일 + 면책(가격은 수시 변동)

### 2.4 분량·표·이미지
- 본문 2,000~3,000자(하한 1,500). 제품 5개 TOP형은 제품당 250~400자.
- 표 2개 이상 권장: 가격표 1 + 스펙 비교표 1. 열 3~5. [관찰 대비 차별화]
- 이미지: 제품 공식 이미지 제품당 1장, 가격 추이 그래프 1장, 비교 요약 이미지 1장. 총 6~10장.
- 모든 가격 숫자에 "(YYYY.MM.DD 기준)" 또는 표 제목에 기준일.

### 2.5 도입·마무리 템플릿
도입: `[제품]을 지금 살지, 조금 더 기다릴지 고민되시죠. 최근 30일 가격 흐름만 보면 [결론 한 줄]입니다. 기준일과 판매처별 가격을 표로 정리했어요.`
마무리: `가격은 매일 바뀌므로 구매 전 [판매처]에서 현재가를 한 번 더 확인하세요. 이 글의 가격은 [날짜] 기준이며, 다음 갱신 때 표를 업데이트합니다.`

### 2.6 문체
- 해요체 중심(후기·비교 글 관행) + 가격 설명은 합니다체. 판단 문장은 근거 숫자 뒤에.
- 예시: `최근 30일 평균은 [금액]이고, 지금 가격은 평균보다 [N]% 낮아요.` / `할인 폭이 큰 시기는 보통 [시즌]이었다는 점은 참고하세요.` (추측이면 "~로 보입니다")
- 이모지: 소제목 번호/💰 정도 허용(최대 4개).

## 3. 블로그 C: Tistory · 구글 검색용 생활정보·정책

### 3.1 상위 글 패턴 요약 (Google 대체 표본) [관찰: 소표본 5편 + 일반 원칙 [추정]]
- 길이가 Naver보다 길다: 3,000~8,000자. H2/H3 위계가 명확(H2 5~9). 목차(번호 5~9항) 존재.
- 최상단 요약 박스(2건) 또는 하단 recap(1건). FAQ 5문항 H3 또는 Q/A 목록 3/5.
- 이미지는 적음(텍스트+표 중심). 표 1~2개.
- 날짜는 게시일만, "수정일" 표기 거의 없음 -> 갱신일 표기는 차별화 [추정].
- 어미는 해요/합니다 혼재. 이모지 0~소량.

### 3.2 제목 공식 (title 태그 50~60자 이내)
- `[연도] 키워드 | 대상·금액·신청방법 총정리` 
- `키워드, [귀속연도] 기준 일정과 신청 순서` 
- 규칙: 키워드 맨 앞, 연도·"총정리/일정" 같은 의도어, 파이프 뒤 부제. 블로그명 접미 불필요(Tistory 자동).

### 3.3 섹션 순서 템플릿
1. 요약 박스(3줄) -- 최상단
2. 목차(번호 링크)
3. H2 정의/개요 -> H2 대상 -> H2 금액 -> H2 일정(표) -> H2 신청 방법(번호 단계) -> H2 놓치기 쉬운 점 -> H2 FAQ(H3 질문 5개) -> H2 출처
4. 마무리 3줄 recap + 마지막 업데이트일
5. 관련 글 내부링크 카드 2~3

### 3.4 분량·표·이미지
- 본문 3,000~5,000자(복합 주제 6,000). 하한 2,000.
- 표 2~3개(대상 기준 / 금액 / 일정). `<table>` 실제 HTML 표 사용(Google이 읽음). 
- 이미지 3~6장, 모두 alt 텍스트(키워드 포함하되 자연스럽게). 공식 화면 캡처 + 요약 인포그래픽.
- 외부 링크: 공식 사이트 2~4개(홈택스·복지로·정책브리핑), rel 속성은 기본.
- 구조화: FAQ는 H3+짧은 답변(스니펫 노출 유리) [추정].

### 3.5 도입·마무리 템플릿
도입: `[제도]는 [대상]이 [혜택]을 받는 제도입니다. 이 글은 [기준일] 기준으로 대상, 금액, 신청 방법을 순서대로 정리했습니다. 먼저 핵심 3가지만 확인하세요.`
마무리: `핵심만 다시 정리합니다. 1) [대상]은 [조건]. 2) 기한은 [날짜]. 3) 신청은 [경로]. 제도는 해마다 바뀔 수 있으므로 신청 전 공식 안내를 함께 확인해 주세요. (최종 확인: YYYY.MM.DD)`

### 3.6 문체
- 합니다체 중심, 문장 짧게, 군더더기 없는 정보 전달. 1인칭 경험 서술 지양.
- 예시: `신청 기한은 [날짜]까지이며, 기한이 지나도 [조건]이면 신청할 수 있습니다.`
- 이모지는 ✔ 정도 recap에만.

## 4. 블로그 D: Tistory · 구글 검색용 가격 데이터형 쇼핑

### 4.2 제목 공식 (50~60자)
- `제품명 최저가·가격 추이 (YYYY년 M월 기준)`

- 규칙: 키워드 + 의도어(최저가/가격 추이/비교) + 기준 시점.

### 4.3 섹션 순서 템플릿
1. 제휴 고지 박스(최상단, affiliate_notice 규칙)
2. 요약 박스: 현재가·기간 최저가·판단 (3줄) + 가격 기준일
3. 목차
4. H2 가격 추이 (표 + 차트) -> H2 지금 사도 되는가(타이밍 근거) -> H2 제품 비교표 -> H2 제품별 상세(H3) -> H2 구매 전 체크리스트 -> H2 FAQ -> H2 데이터 출처·갱신 이력
5. 마무리 recap + `최종 업데이트` 날짜 + 갱신 이력 1줄

### 4.4 분량·표·이미지
- 본문 2,500~4,500자(하한 2,000). 제품 TOP형은 제품당 300~500자.
- 표 3개: 가격 이력표(날짜/최저/평균/판매처), 스펙 비교표, 구매 체크표. 실제 HTML 표.
- 이미지 5~8장: 제품 이미지(alt에 제품명), 가격 추이 차트(alt에 요약 문장), 비교 요약.
- 구조화 데이터는 PRODUCT_JSONLD 플래그 정책에 따름. 가격 JSON-LD는 실제 표기가격과 일치할 때만.
- 링크: 구매 링크는 섹션 끝 CTA 버튼 1개, 과도한 반복 금지.

### 4.5 도입·마무리 템플릿
도입: `[제품]의 최근 가격 흐름을 [기간] 데이터로 정리했습니다. 현재가는 [금액]이고, 기간 최저가는 [금액]입니다. 구매 시점을 판단하는 기준과 비교표를 아래에 담았습니다.`
마무리: `정리하면 지금 가격은 [평균 대비 상태]입니다. 가격은 수시로 바뀌므로 [판매처]에서 현재가를 확인한 뒤 결정하세요. 이 글의 가격은 [날짜] 기준이며 갱신 시 표를 수정합니다.`

### 4.6 문체
- 합니다체, 추측은 "~로 보입니다", 확정은 데이터 뒤에서만. 과장어(최고, 대박, 역대급) 금지.
- 예시: `최근 30일 최저가는 [금액]이며, 현재가는 이보다 [N]% 높습니다.` 
- 이모지 거의 사용하지 않음.

## 5. Naver 상위 vs Google 상위 차이 (정리)

| 항목 | Naver 상위 [관찰] | Google 대체 표본 [관찰/추정] | 우리 적용 |
|------|-------------------|-------------------------------|-----------|
| 길이 | 평균 2,100자, 후기형은 이미지로 분량 채움 | 3,000~8,000자, 정보 밀도 높음 | A/B 1.8~3천, C/D 2.5~5천 |
| 구조 | 질문·번호 소제목(인용구 컴포넌트), 짧은 문단 | H2/H3 위계 + 목차 + 요약 박스 | C/D는 시맨틱 헤딩과 목차 필수 |
| 요약 | 도입 결론 문장 또는 3줄 | 최상단 박스 | 모두 상단 3줄 |
| 표 | 정책 60%, 쇼핑 20% | 정책 표 1~3개, 가이드형 9~10개 | 표는 실제 `<table>`, Naver는 스마트에디터 표 컴포넌트 |
| 이미지 | 8~10장, 직접 촬영·캡처 중심 | 3~6장 + alt, 도식 중심 | Naver 6~9, Tistory 3~6 |
| 어미 | 합니다 85%(정책), 해요 우세(쇼핑 후기) | 해요/합니다 혼재 | A 합니다+해요, B 해요, C/D 합니다 |
| FAQ | 27%(정책), 7%(쇼핑) | 60% (5문항) | C/D FAQ 필수, A/B 선택 |
| 출처 | 일부 말미 목록 | 본문 링크 + 면책 | 모두 말미 출처·확인일 |
| 날짜 | 거의 없음 | 게시일만 | 모두 기준일 + (Tistory) 최종 업데이트 |
| 제휴 고지 | Naver 시스템 라벨에 의존(본문 거의 없음) | 대부분 없음 | 우리는 최상단 본문 고지 의무 |
